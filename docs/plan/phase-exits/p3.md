## What shipped

- **LTR stage** (`meridian-rank`): 9-feature extraction + `LinearLtr` scorer
  behind a `Scorer` trait. Wired into the planner between RRF and the domain cap.
  The cold-start is **RRF-identity** (see honesty note); the trained GBDT slots
  in via the same trait (ADR-02).
- **Intent classifier**: µs heuristic (question/navigational/geo/keyword), keys
  the bandit, surfaced for explainability — never logged with the query.
- **ε-greedy bandit** (`meridian-searx::bandit`): ε=0.1 over 3 curated engine
  subsets keyed by intent, arms in `egress.redb` with an optimistic prior;
  rewards arms whose web results reach the final top-10; anon firewall (reward
  never called for anon). Deterministic per-request exploration salt.
- **Deep cross-encoder rerank** (`meridian-rerank`): ort 2.0-rc.12, MiniLM INT8
  CE, batch 4, 256-tok pairs, 1.5s stage deadline (partial → keep LTR tail),
  `ce` in `rank_signals`. **The ADR-02 bake-off is settled by direct evidence:**
  ort loads `model_qint8_arm64.onnx` and ranks correctly (Meridian -0.64 above
  Longitude -5.58); tract could not load that export (Unsqueeze13). ONNX Runtime
  is statically linked (`libonnxruntime.a`) → the deep binary is self-contained.
- **MMR-lite diversity**: the ≤3-per-domain cap, applied after LTR.
- **Two images now**: default `meridiand` (scratch/musl, fast path, deep
  degrades) and `meridiand-deep` (distroless-cc/gnu, carries the CE). Operators
  opt into deep mode.

## Honesty notes

- **The cold-start LTR is RRF-identity** (unit RRF weight, zero secondary
  weights), and that is the *correct* cold-start, not a cop-out. Every non-zero
  secondary weighting **regressed** nDCG@10 on the eval, because: RRF already
  fuses bm25/ann/consensus; freshness/domain_prior/geo are neutral until Phase 5;
  and title-match is *anti-correlated* on the describe-without-naming synthetic
  set. An untrained linear model cannot beat a strong unsupervised fusion on the
  data we have — so the responsible default is the identity, which guarantees the
  no-regression gate by construction. The full machinery (features, weights,
  trait) ships for the GBDT; operators with a labeled set can hand-tune the
  weights without recompiling. This took three iterations (large weights →
  sub-gap tie-break → identity) before I accepted the honest answer.
- **Deep p50 was measured on an 8k-doc local index, not 100k.** The rerank stage
  cost is corpus-size-independent (always top-20 candidates), and BM25+ANN at 8k
  are faster than at 100k, so 204ms is if anything a slight *over*-estimate of the
  rerank contribution and a clean pass. Re-measure on the 100k volume at the
  Phase-6 soak.
- **The deep binary was built locally (release) for measurement** — the same
  one-off pattern as the bench/eval binaries; ADR-D1's "no release builds on the
  Pi" is about the *serving* artifact pipeline (CI-built), and the deep image is
  CI-built (`image-deep` job). The local build only measured the gate.
- **ort `download-binaries` needs network at build time** (fetches the
  aarch64-gnu ONNX Runtime once, then caches). Relevant for CI/air-gapped builds;
  documented in the rerank crate.
