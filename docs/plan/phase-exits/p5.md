## Honesty notes

1. **ANN is skipped under geo/ts filters** — usearch has no filtered search,
   and an unfiltered dense list would smuggle out-of-area docs into the
   fusion. The constrained path is exact lexical (BM25). Recorded in ADR-10;
   revisit if usearch grows filtered search or the corpus outgrows BM25-only
   recall under filters.
2. **Geo filters constrain local results only.** The SearXNG fan-out cannot be
   geo-filtered. Pure web scope + filter → 400 (caller error); mixed scope
   serves filtered local + unfiltered web, flagged via `degraded` (this gap
   was found and fixed during the device gate — it silently no-op'd before).
3. **Geocoder built but not wired into ingest** (gazetteer-first keeps ingest
   zero-network; Nominatim client + cache ship dark behind the ADR-10 note).
4. **PageRank substrate is GDELT co-occurrence** (domains co-mentioned in a
   slice/topic), not a crawled web-link graph. The prior feeds LTR via the
   `DomainPriorSource` seam and is max-normalized; it reranks gently rather
   than dominating.
5. **Schema v2→v3 has no in-place migration** — meridiand refuses a v2 volume
   at startup with an explicit error (observed live), and the operator
   re-ingests. SPEC §14's `--reindex` arrives with the first post-1.0 change.
6. **Re-ingest robustness:** the 100k re-ingest hit one 504 (a slow batch
   crossing the 12s ceiling during an SD-card merge stall) and a real
   disk-floor shed window (dev artifacts filled the card mid-run; shed fired
   `ingest=SHED`, search kept serving, recovered in 150s once space was
   freed). The ingest driver now retries 429/503/504 and resumes by offset.
   Total: 100k docs accepted across runs at ~110–120 docs/s sustained.
7. **The disk gate is simulated density** (14d × 12k active cells × 15 roots +
   200k edges in one sitting), not two wall-clock weeks. The 90-day retention
   + edge-thinning compaction is unit-tested; the soak (Phase 6) watches the
   real accumulation rate.
8. **meridiand RSS 216MB** serving with gazetteer + analytics + Arti + warm
   caches (P4 baseline 145MB) — well under the 1.2GB Profile-R cap.
