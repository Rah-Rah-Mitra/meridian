## §12.5 invariant coverage (hermetic, in CI)

1. **No direct traffic for anon/region requests** — planner level: Arti-down
   injection (lane enabled, not started) fails the search with **zero hits on
   counting canary servers** standing in for both searx backends; transport
   level: a down `Dialer` refuses the CONNECT before any dial (`dial_count == 0`),
   and the `Dialer` seam has no TCP implementation to fall back to.
2. **Anon DNS via Tor** — a reqwest `socks5h` client (the exact construction the
   lane uses) delivers the **unresolved hostname** across the SOCKS boundary
   (domain ATYP); the host resolver is never consulted (`.test` TLD would fail).
3. **SSRF on every lane** — the shared deny table (`meridian-common::netpolicy`,
   single source for ladder + SOCKS) refuses private literals / cloud metadata /
   non-allowlisted ports / `.onion` (unless `allow_onion`) at the SOCKS server
   with REP 0x02, before the dialer; ladder tests from P1 still cover
   direct/region resolve-then-pin.
4. **Lane-global rate limits** — by construction: ONE keyed `DomainBudget` at one
   chokepoint, lane-blind (`budget.rs` P1 tests); the anon ladder path calls the
   same `acquire`.
5. **`effective_lane` truthful** — local scope reports `local-only` whatever lane
   was requested; direct web reports `direct` with the backend actually hit;
   anon/region that can't serve NEVER return a mislabeled result (they error).

Plus: RFC1929 username→`IsolationToken` mapping (distinct users → distinct
tokens, stable per user) at both the SOCKS layer and the `TokenMap` unit level.

## What shipped

- **Anon lane** (`meridian-egress::anon`): embedded `arti-client` 0.43 on the
  shared Tokio runtime, background bootstrap with observable progress
  (`/v1/lanes`: `bootstrapping nn%` → `up`), state under `<data>/arti` (single
  mutable volume). **One egress path**: a hand-rolled CONNECT-only SOCKS5
  front-end (ADR-04: arti's own proxy is experimental-API) over a `Dialer` seam
  whose only production impl is `TorClient::connect_with_prefs`. `searxng-anon`
  proxies through it (`socks5h`, per-connection isolation token); Meridian's own
  anon fetches ride it too with a fresh RFC1929 username per logical request
  (full per-request isolation). Circuit cap (semaphore, default 6), stream
  lifetime cap, destination policy in the server.
- **Fail-closed, three layers**: planner refuses anon unless Arti is
  `ready_for_traffic` AND `searx.anon_url` is configured; the per-request client
  owns ONLY a loopback-SOCKS transport; the SOCKS server refuses CONNECTs while
  the dialer isn't ready. Compose topology adds the fourth: `searxng-anon` lives
  on the internal `back` network whose sole egress is the listener.
- **Anon isolation in shared state**: ephemeral 32MB/TTL-5m anon query cache
  (separate moka instance, in-memory only); bandit neither chooses nor rewards
  for anon (engine set = instance defaults, `chosen_arm` never set); no hedging;
  region results never cached; fetch cache stays direct-only. Anon admission
  budget: 2 concurrent searches → 503 `anon lane busy`.
- **Region lanes** (`meridian-egress::region`): per-region pooled + pinned
  clients with `local_address` source-IP bind; bring-up + 30-min re-verification
  against an operator-configured IP-echo endpoint; **unverified or mismatched
  lanes refuse traffic** (a leaking region lane is a leak, not a degraded lane).
  Region + web scope fails closed (no metasearch backend can serve a region
  vantage without breaking invariant 1) — regions serve `/v1/fetch`/ingest.
- **Deploy**: anon profile riding `.env` (`MERIDIAN_ANON=true` + `--profile
  anon`), `compose.regions.yaml` host-network overlay (documented tradeoffs,
  anon-incompatible), `wg-lane-templates/make-region.sh` generating
  operator-reviewed `ip rule` scripts (never auto-applied).
- `/v1/lanes` returns machine-readable `status` + human `detail` per lane,
  including each configured `region:<id>`.

## On-device anon transport drill (2026-06-11, host-run debug binary)

End-to-end through the real Tor network (the full in-process path: SOCKS
front-end → ArtiDialer → circuit → exit), independent of the sidecar:

- **Bootstrap window is fail-closed and observable**: 4s after start,
  `/v1/lanes` reported `anon bootstrapping 15%` and an anon fetch returned
  **503**; zero requests served before `ready_for_traffic`.
- **Bootstrap → `up` in ~58s** (cold Arti state dir, debug binary; Phase-0
  release bench measured 14.7s — bootstrap is once per state dir, then cached).
- **In-core anon fetch** (`/v1/fetch?lane=anon`, example.com): 200 OK at
  **1.8s / 1.3s / 1.2s** — robots + GET on one circuit family per request.
- **Exit-IP proof**: icanhazip.com through the lane returned **45.66.35.24**
  (a Tor exit) vs the appliance's WAN **116.14.203.78**. (checkip.amazonaws.com
  times out via Tor — AWS throttles exits; irrelevant to region lanes, which
  don't traverse Tor.)
- Two findings fixed during bring-up: (a) arti's fs-mistrust audit needs the
  passwd/group database → `dangerously_trust_everyone()` with the
  single-tenant-volume justification recorded in code; (b) even with mistrust
  disabled, fs-mistrust still resolves the CURRENT user via getpwuid, and musl
  errors outright when /etc/passwd is absent → the scratch image now carries a
  three-line passwd/group for uid 65534.

## On-device region drill (2026-06-11)

No WireGuard endpoint exists in this environment, so the drill bound the lane to
the host's own address (`source_ip = 192.168.1.1`) and verified the *mechanism*:

- `expected_ip = 203.0.113.99` (wrong on purpose) → `/v1/lanes`:
  `region:local degraded — "egress ip mismatch (observed 116.14.203.78)"`;
  `/v1/fetch?lane=region:local` → **503**. The tripwire trips.
- `expected_ip = 116.14.203.78` (the real egress) → `region:local up`;
  `/v1/fetch?lane=region:local&url=https://example.com/` → **200** in 166ms,
  clean extraction. The verified path serves.

## Honesty notes

- **searxng-anon isolation is per-CONNECTION, not per-query** (SearXNG's proxy
  URL is static; it cannot vary RFC1929 credentials). Stronger than arti's
  no-auth proxy default; weaker than the spec's ideal — httpx pooling can carry
  several queries' engine hits over one tunnel. Recorded in ADR-04 amendments +
  threat model. The in-core path has true per-request isolation.
- **The region drill used the host's own IP, not a WireGuard interface** — no WG
  endpoint is available here. What Phase 4 ships (source-IP bind, echo
  verification, fail-closed gate, ip-rule templates) is exactly what an operator
  with real WG endpoints consumes; the bind-to-wg-address path is the same
  `local_address` call. GeoLite2 region-name matching deferred to Phase 5.
- **Hermetic Arti-down ≠ packet-level proof.** The §12.5 inv-1 tests prove the
  failure semantics at the planner and SOCKS layers with counting canaries; the
  Phase-6 chaos drill (kill Arti under load, egress capture) remains the
  packet-level confirmation, as planned.
- **CI temp-dir collision** (`subsec_nanos` names) broke the first CI run of the
  invariant suite on the faster runner — fixed with a process-wide counter.
  The Pi never reproduced it; parallel-test hygiene, not a product bug.
- **The gate image was assembled locally** from CI run 27292852969's byte-exact
  binary + models artifact plus the passwd/group Dockerfile fix (the fix
  postdates that run's image job); the next CI run rebuilds the identical image
  in-pipeline. One privacy-smoke failure on that run was a HuggingFace 429
  (three CI runs in quick succession) — green on rerun, nothing product-related.
- **Incidental shed validation**: local build debris pushed the card under the
  768MB disk floor mid-gate — `meridian_shed_state{stage="ingest"} 1` appeared,
  and cleared by itself after cleanup. The ladder works outside of tests.
- **Anon search latency mixes Tor variance**: cold circuits land anywhere in
  1–8s; SPEC's single-attempt/no-hedge anon policy means slow ones surface to
  the caller (now as a slow 200 or an honest searx-deadline degradation, not a
  premature API 504).
