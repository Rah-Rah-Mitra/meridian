## Key derived numbers (now feeding `02-budgets.md`)

- **`ef_search = 64` validated** as the operating point (smallest swept ef with
  recall ≥0.95): recall@10 0.98 at p99 0.95ms. ef=128 buys recall 1.00 at p99
  1.45ms — both trivially affordable; keep 64 default, 128 is free headroom.
- **USearch @1M:** 506MB resident (budget 520MB ✓); build 2,584 vec/s concurrent
  (1M ≈ 6.5 min — irrelevant to incremental ingest); `view()` works on 16K pages
  (ADR-01 closed).
- **BM25 latency curve** is ~linear-ish in corpus size and leaves ~62× headroom at
  100k; extrapolated 1M (Profile F) ≈ 2–5ms p50 — far inside the 30ms gate.
  Caveat: simplewiki docs are short (527 B/doc indexed); real web pages are larger.
- **Ingest** is fetch/extract-bound as predicted: indexing alone does 15k docs/s
  vs the ≥50/s system gate (300×).
- **fast-mode local p50 budget** (normalize+BM25+embed+ANN+RRF+LTR+render): every
  measured stage sums to **<5ms** at Profile R scale vs the 80ms target.
- **Anon lane:** the ≤8s deadline holds comfortably *after* bootstrap (connect p50
  1.1s); cold bootstrap (14.7s) must be excluded from request deadlines —
  bootstrap at startup/lane-enable, surface `Bootstrapping(pct)`. Arti RSS +55MB
  ≪ the 80–150MB budget; dir cache 43MB ≪ 200MB cap.

## Findings & methodology notes (chronological, all preserved in git)

1. **tract/zigbuild toolchain gap:** tract-linalg passes `-march=…+sve+fp16` (GCC
   spelling) — zig's clang rejects it, so tract cannot cross-compile to musl via
   zigbuild today. Bench builds use the GNU toolchain; recorded in ADR-02 (Plan A
   needs an upstreamable tract fix or vendored build.rs patch by Phase 3).
2. **tract op-coverage gap:** the official `model_qint8_arm64.onnx` CE fails tract
   0.23 analysis at node `/bert/Unsqueeze` (Unsqueeze13) at every batch size.
   Deep-rerank cost remains unmeasured; Phase-3 bake-off starts with a
   tract-friendly (re-)export or Plan B (ort + gnu/distroless).
3. **ANN recall methodology** took three iterations to make honest:
   uniformly-random 256-d vectors → distance concentration, recall 0.012
   (meaningless); Gaussian mixture + hand-rolled i8 reference → 0.86 plateau
   across the whole ef sweep (representation mismatch signature); truth from
   usearch's own `exact_search` (identical stored vectors + kernel) → recall 0.98
   @ ef=64. The suite now measures graph recall by construction; f32-vs-i8
   quantization loss is owned by the Phase-2 quality eval (nDCG hybrid ≥ BM25).
4. **1Hz disk sampler** can under-report short merge transients (53MB index merges
   in ~1s); fine at Profile R, re-check at Profile F scale where merges take
   minutes.
5. Corpus caveat: simplewiki abstracts/articles capped at 5KB — BM25 numbers are
   optimistic vs heavy web pages; Phase-2 eval uses the operator corpus.
