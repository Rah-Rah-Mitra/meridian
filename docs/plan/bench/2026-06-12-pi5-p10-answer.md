# Suite 18 `answer` — Phase-10 entry experiment (2026-06-12, Pi 5)

**Verdict: GATE PASS. ADR-29 confirmed; `ANSWER_FETCH_COST = 0.1` frozen**
(tuning-seed sweep, a-priori rule: max hit-rate, fewer fetches as
tie-break). Machine-readable run: `2026-06-12-pi5-p10-answer.json`.

## What was measured

1000-query hermetic replay (suite-15 shape + answer structure: 3 decisive
originals per query, ONE carrying THE answer passage; syndicated copies
carry truncated versions — a copy is a worse place to read the answer than
its original; 11 chaff). Budget = the production `deep_fetch_max` (2).
Three policies on the hold-out seed with the frozen constant:

| Policy | hit-rate | mean fetches |
|---|---|---|
| **answer mode** (`pandora_walk`, passage-CE units) | **0.700** | **1.65** |
| additive page selector (the v0.4.0 rule, same budget) | 0.183 | 2.00 |
| snippet-head baseline (no fetch, CE over snippets) | 0.593 | 0 |

- **+10.7pp over not fetching** (gate: +10pp): reading the top candidates
  corrects the snippet-noise cases where the best-looking doc does not
  actually contain the best passage.
- **3.8× the page selector's hit-rate at FEWER fetches** — the cleanest
  measurement yet of ADR-26's regime split: the additive rule optimizes
  page-level nDCG (it reads high-headroom docs, not best-passage
  candidates) while Weitzman's rule optimizes the single best find. Each is
  the right policy for its own objective, and they are different policies.
- The unit system is deliberate: answer mode prices fetches in passage-CE
  units (gain = novelty, realized = best passage CE, incumbent starts at 0)
  — `DEFAULT_FETCH_COST` (0.6, DCG units) does not transfer and was not
  reused.

## Honesty notes

- **Harness-construct v0 documented**: the first run gave the SELECTOR only
  the raw retrieval score while the baseline read the snippet-CE — but the
  production fetch phase runs AFTER the deep snippet rerank, so the
  selector's score signal includes snippet-CE. v0 measured the selectors at
  0.10 vs the baseline's 0.54 purely through that starvation. The fixed
  replay mirrors the production information set.
- **An n=300 run measured +9.7pp — a 0.3pp gate near-miss.** The resolution
  was MORE replay (n=1000 stabilizes the estimate at +10.7pp), not a gate
  change; recorded so nobody mistakes the sequence.
- The dead-field cleanup changed the generator's rng stream; the suite was
  re-run and re-frozen on the final stream (hit 0.700/0.593; the sweep
  re-chose cost = 0.1).

## Production wiring (same train)

`answer=true` (requires `fetch_budget ≥ 1`, inherits every restriction) ·
inline Pandora stop (open the best reservation index unless the passage
value in hand meets it) · per-fetch passage-CE batch realizes the walk's
value (suite semantics mirrored exactly) · `best_passage {schema, text ≤500
chars, url, ce_score}`, extractive only, "relevance not correctness" wording
in api.md · `degraded: ["answer_unavailable"]` when empty-handed ·
`search.answer_deadline_ms` (1800ms default) with its own budget row
(answer p50 ≤3.0s — the deep 2.5s budget is not silently busted) · inv21
(fails safe without a CE; anon lane never reaches the phase).
