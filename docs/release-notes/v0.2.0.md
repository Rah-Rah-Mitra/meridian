# Meridian v0.2.0 — the evidence release

Phase 7 complete (exit note: `docs/plan/phase-exits/p7.md`). Meridian stops
being only a metasearch fuser and starts telling you **how independent your
sources actually are** — locally, explainably, and deletably.

## Source-independence evidence in `/v1/search`

Every document ingested by v0.2.0+ carries a 64-byte derivation sketch
(one-permutation b-bit MinHash over word shingles), written in the same
transaction as the dedup rows and erased in the same transaction by
`/v1/forget` — a sketch can never outlive its document. At query time, results
are clustered by **containment** (the suite-9 experiment showed raw Jaccard
fails on real syndication: truncation + boilerplate), and the response carries:

- per-result `evidence.cluster` — which derivation cluster a result belongs to;
- an `evidence` block — `independent_source_count` vs `apparent_source_count`,
  with per-cluster `members`/`domains` (members > domains = cross-domain
  syndication, the case plain domain grouping is structurally blind to —
  measured baseline F1 0.054 vs 0.995 for the sketch clustering).

Honesty contract: only documents with full-text sketches participate; web
results never fetched stay `evidence: null` — independence is never guessed
from a snippet. Kill-switch: `[evidence] enabled` (default on). Documents
ingested before v0.2.0 have no sketches until re-ingested (the dedup table
makes back-filling impossible by design — forgotten content stays forgotten).

Measured on the Pi 5: the whole stage adds **+0.2ms p50** (A/B against its own
kill-switch on the live 100k deployment).

## Statistically defensible trends & heatmap

The naive latest/window-mean "movers" are replaced (ADR-21, fixed by a
planted-spike study) by empirical-Bayes shrinkage with an
**overdispersion-aware quasi-NB z-scale** and Benjamini-Hochberg FDR:

- `/v1/trends` movers now rank by `z` and carry `shrunk_rate`, `q_value`,
  `significant`, and an honesty `label` ("likely low-sample noise") when a
  ratio looks dramatic but the statistics cannot back it. Raw `ratio` stays.
- `/v1/geo/heatmap` cells gain Getis-Ord Gi* hot-spot statistics over the H3
  k-ring-1 neighborhood (`z`, `q_value`, `significant`).

Measured: 3.76× fewer false spikes at matched true-positive rate (Poisson
regime), 1.81× with held FDR on an overdispersed hold-out; heatmap with the
statistics at 23.7ms p50 @100k docs.

## Early Phase-8 preview: `compare=vantages`

`GET /v1/search?q=…&scope=web&compare=vantages` runs the same query over the
direct AND anon (Tor) lanes and attaches a `divergence` block: Jensen-Shannon
divergence between the lanes' domain distributions, `domains_only_in_*`, and
the deployment's measured same-lane noise floor as the reference. Explicitly
opt-in (the query is intentionally observable from two vantages — see
privacy.md), fail-closed (an unavailable anon lane errors the whole compare),
cache-bypassing on both halves, with randomized inter-lane jitter on by
default. The population-level divergence gates land with v0.3.0.

## Fixes

- **Dense (ANN) recall restored** — latent since v0.1.0's lineage: the
  Phase-2 switch to usearch's portable C++ backend (a build workaround)
  silently collapsed i8 recall at corpus scale (measured 0.0 recall@10 at 1M
  vectors vs 0.999 on the SIMD backend; masked in day-to-day use by
  BM25-dominant fusion). The numkong SIMD backend is restored — its current
  build script drops the zig-incompatible SVE/SME kernels cleanly, which the
  Phase-2-era version could not. The synthetic recall gate now re-runs at
  every release. If your deployment leaned on dense/semantic matches, expect
  visibly better related-document retrieval.
- `MIN_MATCH_BINS` floor in the sketch estimator: a chance quantization
  collision against a tiny document could amplify past the derivation
  threshold (caught live by the exit drill, now regression-tested).
- Tombstone refusals are now visible: `POST /v1/ingest` responses carry
  `refused` (re-ingest of forgotten content was always blocked, but silently).
- gitleaks CI job: PR-scan permissions.
- Flaky gazetteer test: parallel FST writes raced on one temp file.

## Operator notes

- New config: `[evidence] enabled` (default true), `search.compare_jitter_ms_max`
  (default 30000), `search.compare_noise_floor_p90` (set from your suite-12
  probe), and mind `search.searx_deadline_ms` — the 800ms default is too tight
  for some networks (this deployment needed 2500ms for reliable direct
  websearch).
- API changes are additive-only (ADR-20); every new block carries a `schema`
  field.
