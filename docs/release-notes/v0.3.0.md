# Meridian v0.3.0 — the divergence release

Phase 8 complete (exit note: `docs/plan/phase-exits/p8.md`). The flagship
claim is now a measured fact, not a pitch: **the same query, asked from two
network vantages, returns measurably different source distributions** — and
Meridian quantifies it per request, with the lane isolation to make the
comparison honest.

## `compare=vantages` is gated and graduated

`GET /v1/search?q=…&scope=web&compare=vantages` (previewed in v0.2.0) passed
its population-level gate on this deployment: across a curated
region-sensitive query set, cross-lane (direct vs Tor) Jensen-Shannon
divergence averaged **0.71 against a same-lane noise floor of 0.10** —
roughly 7× the noise, bootstrap p≈0. What changed since the preview:

- **Empty halves refuse instead of agreeing.** If either lane returns zero
  web results the compare errors (`jsd(∅,∅)=0` would fabricate "no
  divergence" — the gate run itself caught this when both sidecars were
  down). The direct half is checked before any Tor circuit is spent.
- **Both halves pin engines and bypass caches** — the suite-12 probe showed
  the ε-greedy bandit's arm churn alone produces p90 JSD 0.67 within one
  lane; pinning makes the halves differ by vantage only.
- **The inter-lane jitter is clamped to the request ceiling and disclosed.**
  Under default config the synchronous budget leaves well under a second of
  jitter; privacy.md now says exactly what that does and does not
  decorrelate, instead of implying more.
- 17 hermetic egress invariants (up from 13 at v0.1.0) pin the isolation:
  no shared-cache writes, no bandit reward from compare, anon-down means
  refusal not retry, empty-half refusal.

## Confidence on every response

The `confidence` block (ADR-23) carries two cheap, explainable
query-performance predictors (NQC, clarity) and a blended score, computed in
well under a millisecond. Measured against per-query nDCG@10: Spearman
ρ=0.256 (gate ≥0.25), ECE 0.065. It is a hint for agents and UIs — "how much
should you trust this ranking" — not a calibrated probability, and api.md
says so.

## What did NOT ship, on purpose: `diversity=mmr`

An MMR diversity rerank was built for this release and **withdrawn by its own
gate**. On a duplicate-heavy benchmark (two generator seeds, λ swept
0.5–0.95), token-overlap MMR improved subtopic coverage (alpha-nDCG) only at
a 7–11% plain-relevance cost: symmetric similarity cannot tell a canonical
original from its syndicated copies, and since copies are shorter (higher
BM25), the original is what gets demoted. Per the project's bench-first rule
a failed gate does not ship dark or flagged — the parameter is gone.
Replacement on the roadmap: diversity via the Phase-7 evidence clusters,
which already know each cluster's canonical representative.

## Phase-9 substrate (dark in this release)

- `searx.decision_log` (**default off**): a per-decision routing log whose
  rows are 13 bytes of coarse buckets + arm/propensity/reward — no query
  text, no URLs, no IPs, nothing finer than a 3-hour time bucket; k-anonymity
  floor, 30-day TTL, 20MB cap; anon-lane decisions are never logged (the
  lane firewall extends to the log, pinned by hermetic invariant 18).
  Operator surface ships with it: `GET /v1/decision-log` (status) and
  `POST /v1/decision-log/wipe` (erasure), both bearer-gated. See privacy.md
  for the full contract. It exists so a future routing policy can be
  evaluated OFFLINE before any live traffic shifts.
- The offline-policy-evaluation harness that will consume it passed its
  validity gate: IPS and doubly-robust estimators recover a known synthetic
  truth within 2.0% / 0.74% (gate <5%) under the exact logging policy the
  bandit ships.
