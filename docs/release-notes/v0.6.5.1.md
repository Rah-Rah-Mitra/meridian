# Meridian v0.6.5.1 — operator console v2, per-request tuning, deep image live

A console + activation release: the embedded operator console is redesigned into
a dense, modern, still-zero-dependency control surface; a clamped per-request
tuning layer (ADR-30) exposes the full engine; and the **deep/gnu image is now
published and deployed**, so deep mode / answer mode / C1 corroboration are
LIVE on the appliance instead of dormant.

## Operator console v2 (`/ui`)

Still vanilla ES modules + hand-rolled `<canvas>`, baked into the binary via
`include_bytes!` — no build step, no dependency, no CDN (~153 KB total). The
redesign keeps **every** honesty discipline verbatim (uncalibrated-confidence
label, `ce_score` = "relevance not correctness", independent-vs-apparent source
counts, abstention / `insufficient_data` as first-class calm states, all
`degraded[]` flags, the lane-mismatch badge, no blank boxes) and stays GET-only.

- A left **sidebar** routes between views (hidden views do no network/draw); a
  **topbar** holds the session-only token input, a **light/dark theme** toggle
  (the only persisted UI state; the bearer is never stored), and a **version • CE**
  pill.
- **Search** gains the full control set (mode, scope, lane direct/anon/region,
  limit, answer, fetch_budget, diversity, compare, geo lat/lon/radius **or** h3,
  time window) and an **Advanced / Tuning** drawer pre-filled from `/v1/config`.
  Renders every response block incl. `best_passage.corroboration`, the VoI
  `analysis` block, and an `applied_overrides` readout.
- New **metrics** panel (client-side Prometheus parse → uptime, request
  rates, latency p50/p90/p99, storage/cache/shed, free disk, GDELT rows) and
  **deploy** panel (read-only effective config + which features are live vs
  dormant + the contextual-policy gate explained).
- Charts gain hover tooltips; geo gains a `q` filter, colormap legend and
  per-cell hover; trends gains topic / window / h3 selectors.

## Per-request tuning overrides (ADR-30)

`GET /v1/search` accepts 18 flat `ov_*` params (e.g. `ov_bm25_top_k`, `ov_rrf_k`,
`ov_containment_tau`, `ov_answer_passage_cap`, the CE/fetch deadlines). Each
replaces its config default for that one request, is **clamped (saturated) to a
safe range** rather than rejected, and is echoed back (clamped) in
`applied_overrides`. A misspelled knob is a loud `400` (`deny_unknown_fields`).
The previously-hardcoded query-time constants (`RRF_K`, `containment_tau`, the
rerank / passage / corroboration CE deadlines) were promoted to config to enable
this; the consts remain the canonical defaults.

**Privacy & budgets.** Overrides persist nothing, are never logged with the query
text, and key the result cache (tunings never collide). The **no-override path is
byte-identical** to before — every read is `req.overrides.X.unwrap_or(cfg.X)` and
each default equals its prior const — so the measured budgets hold (`fast ≤25 ms /
deep p50 ≤2.5 s / answer p50 ≤3.0 s`); only an explicit override may loosen a
deadline. Re-confirmed live on the deployed image (no regression).

`GET /v1/config` (bearer-optional) serves the tunable defaults + safe ranges +
rationale (the drawer's source), the read-only deploy config with each env var,
and feature availability — never any secret (no token, no internal URLs/paths).

`ef` (`vector.expansion_search`) is deliberately **not** a live knob — it is
applied store-wide, so per-request variation would race shared index state; it is
surfaced read-only instead. Honesty over a fake live knob.

## Deep image published & deployed (ADR-31)

`release.yml` now builds and pushes the deep/gnu variant
(`deploy/Dockerfile.deep`, distroless/cc, aarch64-gnu, `--features rerank-ort`,
ms-marco-MiniLM INT8 baked) as **`:0.6.5.1-deep-arm64`** alongside the scratch
multi-arch tags, with its own SBOM. The scratch image stays the canonical
published default (`:latest` / `:0.6.5.1` — ADR-02 unchanged); the deep image is
an explicit opt-in variant. The live appliance is refreshed to the deep tag on
the **preserved v5 data volume (no re-ingest** — the cross-encoder is query-time
only), activating deep mode, answer mode and C1 corroboration. arm64-deep only
(the live box is a Pi 5); amd64-deep deferred (no current consumer).

## Left dark for cause

- **`searx.contextual_policy`** stays OFF (ADR-25). Its ship-gate (doubly-robust
  uplift CI excluding zero on ≥10k logged decisions) is unmet — the live log has
  a handful of organic searches — so enabling it would route on an unvalidated
  policy. The deploy/OPE panels explain this; ε-greedy routing stays.
- **Region lanes** stay `disabled` — they need real per-region WireGuard egress
  endpoints to provision (see `docs/region-lanes.md`); the console supports them
  first-class and documents the turn-key recipe, but never claims a vantage it
  can't route from.

## Notes

Cargo.toml stays `0.1.0`; the image/`/v1/config` version is the git tag, injected
at build via `MERIDIAN_BUILD_VERSION`. anon lane, GDELT analytics/trends, geo
heatmap and the decision log were already live and remain so.
